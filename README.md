# 캠퍼스 분실물 찾기

학교에서 잃어버린 물건, 등록 한 번으로 빠르게 찾아주는 캠퍼스 분실물 서비스 소개 페이지입니다.

UI/UX 프로그래밍 수업에서 주차별로 이어서 만들고 있습니다.

- 배포 주소: https://han-sungmin.github.io/uiuxprogramming/

## UX 계획

`index.html`의 `<body>` 첫 줄 주석에도 같은 내용을 남겨두었습니다.

- 사용자: 학교에서 물건을 자주 잃어버리거나 주운 물건을 어떻게 돌려줘야 할지 모르는 학생
- 목적: 잃어버린 물건을 빠르게 찾거나, 주운 물건을 쉽게 등록해 돌려준다
- 핵심 행동: 원하는 영역으로 이동한다 · 이메일로 습득 알림을 신청한다
- 정보 순서: 서비스 소개 → 주요 기능 → 이용 방법 → 알림 받기

## 2주차 HTML 구조 기록

`header`, `nav`, `main`, `section`, `footer`로 페이지를 나누고 메뉴 링크를 누르면 각 영역으로 이동하도록 만들었습니다.
기능 3개는 `ul`, 이용 방법은 순서가 있어서 `ol`로 작성했고, 이메일 입력은 `label`과 `input`의 `id`를 맞춰 연결했습니다.

### 구조를 바꾼 부분
- 처음 계획: 서비스 소개 → 이용 방법 → 알림 받기
- 구현 후 변경: 어떤 기능이 있는지 먼저 알아야 이용 방법이 이해될 것 같아서
  서비스 소개 → 주요 기능 → 이용 방법 → 알림 받기로 바꿨습니다.

## 3주차 CSS 수정 기록

### 수정한 내용
기능 카드 목록(`.feature-list`)에 `display: flex`와 `gap: 20px`를 적용하고,
각 카드(`.feature-card`)에 `padding`, `border`, `background-color`를 줘서 카드 형태로 만들었습니다.

### 수정 이유
세 기능이 같은 종류의 정보라는 게 한눈에 보이고, 카드끼리 나란히 놓여 있어서 비교하기 쉽게 하려고 수정했습니다.
카드 사이 간격도 `gap`으로 일정하게 맞췄습니다.

## 4주차 반응형 수정 기록

### 확인한 문제
3주차 페이지를 개발자 도구에서 390px로 줄여보니까 데스크톱 배치가 그대로 남아 있었습니다.
메뉴 4개가 한 줄에 붙어 있어서 누르기 불편했고, 기능 카드는 flex로 되어 있어서
화면 너비에 따라 2개, 1개로 애매하게 나뉘었습니다.
이메일 입력창이랑 버튼도 한 줄에 있어서 입력창이 좁아졌습니다.

### 수정한 내용
- header, main, footer에 `width: 100%`와 `max-width: 960px`를 같이 줘서 화면이 좁아지면 같이 줄어들게 했습니다.
- 서비스 이미지는 `width: 100%`, `max-width: 320px`, `height: auto`로 바꿨습니다.
- 기능 카드 목록(`.feature-list`)을 flex에서 Grid로 바꾸고 `repeat(auto-fit, minmax(220px, 1fr))`를 사용했습니다. Grid에서는 flex-wrap이 안 먹혀서 지웠습니다.
- `style.css` 맨 아래에 `@media (max-width: 768px)`를 하나 만들고 그 안에서
  - 메뉴를 세로로 배치
  - 기능 카드를 한 열(`1fr`)로 배치
  - 이메일 입력창과 버튼을 세로로 배치하고 버튼 높이를 48px로 설정
  - 제목 글자 크기(h1 40px → 32px, h2 28px → 24px)와 여백 줄이기

  로 적용했습니다.

폼을 세로로 바꿨을 때 입력창 아래에 빈 공간이 크게 생겼는데, 기존에 `.email-field`에 줬던
`flex: 1 1 220px`가 세로 방향에서는 높이로 적용돼서 그런 거였습니다.
그래서 768px 이하에서는 `flex: none`으로 바꿔서 해결했습니다.

### 달라진 점
1100px, 769px, 768px, 390px 순서로 확인했습니다.
769px까지는 기존 가로 배치가 유지되고, 768px부터 메뉴, 카드, 폼이 한 열로 바뀝니다.
390px에서도 글자나 이미지가 잘리지 않고 가로 스크롤 없이 볼 수 있습니다.

## 5주차 JavaScript 기능 추가 기록

### 추가한 기능
"알림 받기" 영역의 이메일 신청 폼에 **입력값 검사와 처리 결과 안내** 기능을 추가했습니다.

### 구현 방법
1. `index.html` 맨 아래에서 `<script src="script.js">`로 연결하고, `querySelector`로 폼·입력창·버튼·안내 문구를 선택했습니다.
2. 폼의 `submit` 이벤트에 `handleSubscribe` 함수를 연결하고 `event.preventDefault()`로 새로고침을 막았습니다.
3. `if / else if / else`로 입력값에 따라 다른 안내 문구를 보여줍니다.

   | 입력 상황 | 안내 문구 | 스타일 |
   | --- | --- | --- |
   | 빈칸 | 이메일을 입력해 주세요. | 빨간색(`is-error`) |
   | `@`나 `.`이 없음 | 이메일 형식이 올바르지 않습니다. | 빨간색(`is-error`) |
   | `.ac.kr`로 끝나지 않음 | 학교 이메일만 신청할 수 있습니다. | 빨간색(`is-error`) |
   | 이미 신청한 이메일 | 이미 알림을 신청한 이메일입니다. | 보라색(`is-info`) |
   | 정상 입력 | 습득물 알림 신청이 완료되었습니다. | 초록색(`is-success`) |

4. `classList`로 문구 색과 입력창 빨간 테두리(`is-invalid`)를 바꾸고, 신청이 완료되면 버튼을
   `신청 완료`로 바꾸고 `disabled = true`로 비활성화(회색)해서 중복 신청을 막았습니다.
   입력창 내용을 다시 바꾸면(`input` 이벤트) 버튼이 원래 상태로 돌아옵니다.

### 바꾼 부분
- 폼에 `novalidate`를 넣어 브라우저 기본 경고 대신 직접 만든 조건문 안내가 보이도록 했습니다.
- 서비스가 캠퍼스용이라 일반 이메일 대신 학교 이메일(`ac.kr`)만 받도록 조건을 추가했습니다.
- 긴 이메일 주소가 모바일에서 잘리지 않도록 안내 문구에 `overflow-wrap: anywhere`를 적용했습니다.
