# 캠퍼스 분실물 찾기

학교에서 잃어버린 물건, 등록 한 번으로 빠르게 찾아주는 캠퍼스 분실물 서비스 웹페이지입니다.
UI/UX 프로그래밍 수업에서 1주차부터 이어서 만들고 있으며, 7주차에는 **분실물 신고하기** 흐름을, 중간고사에서는 **내 신고 내역(다시 열기·조건으로 찾기·신고 취소)** 을, 9주차에는 **분실물 신고 폼의 입력 경험(조건부 입력·입력 중 피드백·submit 검사·접수 중/완료/실패 처리)** 을 추가했습니다.

- 배포 주소: https://han-sungmin.github.io/uiuxprogramming/
- 저장소 주소: https://github.com/Han-Sungmin/uiuxprogramming

## 프로젝트 소개

| 항목 | 내용 |
| --- | --- |
| 서비스 | 캠퍼스 분실물 찾기 |
| 주요 사용자 | 캠퍼스에서 물건을 잃어버렸는데 어디에, 어떻게 알려야 할지 모르는 학생 |
| 서비스 목적 | 잃어버린 물건의 정보와 장소를 한곳에 남겨, 비슷한 습득물이 등록되면 빨리 찾을 수 있게 한다 |
| 핵심 행동 | 잃어버린 물건을 **분실물 신고**로 등록하고, 접수한 신고를 **다시 찾아보거나 물건을 찾으면 취소**한다 |
| 완료 조건 | 물건 정보·장소·연락 방법을 입력하고 확인 화면에서 신고를 확정해, **신고 번호가 적힌 완료 화면**에 도달하고 다음 행동(보관 장소 확인 / 내 신고 내역 / 다른 물건 신고)을 알 수 있다 |

페이지 구성: 서비스 소개 → 주요 기능 → 이용 방법(탭) → **분실물 신고(7주차)** → **내 신고 내역(중간고사)** → 알림 받기

## 9주차: 폼 UI와 입력 경험 — 분실물 신고 폼 개선

7주차에 만든 분실물 신고는 단계마다 버튼(`click`)으로만 값을 검사했고, 오류는 칸이 비었는지만 알려 주었으며, 신고 확정을 누르면 바로 완료되었습니다.
9주차에는 이 신고 화면을 **하나의 `<form>`** 으로 묶어 "무엇을 입력해야 하는지 알고 → 틀린 곳을 바로 고치고 → 제출 결과를 확인"할 수 있게 고쳤습니다.

### 이번 주 추가·수정한 기능

| 구분 | 무엇을 바꿨나 | 코드 위치 |
| --- | --- | --- |
| 폼 구조 | `#reportFlow`(div) → `<form id="reportForm" novalidate>`. 모든 칸에 `name`을 붙이고, 단계 이동은 `type="button"`, 최종 제출(확정 팝업의 `신고 확정`)은 `type="submit"` | `index.html` `#reportForm` |
| label·도움말 | 모든 칸에 `label for`/`id` 연결, 칸마다 입력 조건 도움말(`…Help`)을 추가해 `aria-describedby`로 안내·상태·오류를 함께 연결. 필수 항목에 `필수` 글자 배지 | `index.html` 각 `.report-field` |
| 조건부 입력 ① (체크박스, 새로 추가) | `물건에 이름이나 표시가 적혀 있어요`를 체크하면 `적혀 있는 이름·표시` 칸이 나타나고 입력 가능 | `setConditionalField()`, `handleMarkChange()` |
| 조건부 입력 ② (라디오, 수정) | `학교 이메일로 습득 알림 받기`를 고를 때만 이메일 칸이 나타나고 입력 가능 (7주차엔 숨기기만 했음 → 이제 `disabled`도 함께) | `handleContactChange()` |
| 입력 중 피드백 | 물건 특징·이름 표시: `n / 30자` 글자 수 + `2자 더 입력해 주세요. (지금 0자)` → `✓ 입력 조건을 충족했습니다.` / 이메일: `✓ 알림을 받을 수 있는 학교 이메일입니다.` | `updateFieldStatus()` |
| 검증·오류 | 칸마다 규칙을 함수로 분리(`fieldRules`), 빈 값과 짧은 값을 서로 다른 문구로 안내. 오류가 난 칸은 입력할 때마다 다시 검사해 **고치는 순간 오류 해제** | `fieldRules`, `validateField()`, `handleReportFieldInput()` |
| 제출 차단 안내 | 막히면 폼 위에 `수정이 필요한 항목이 2개 있습니다: 물건 종류, 물건 특징.` + 첫 오류 칸으로 초점 이동. 모두 고치면 안내도 사라짐 | `showFormAlert()`, `checkStep()` |
| submit 처리 | 버튼 클릭과 Enter 키 모두 `submit` 이벤트 한곳으로. 1·2단계에서 Enter = 다음 단계 검사, 3단계 확정 = 전체 재검사 → 저장 | `handleReportFormSubmit()` |
| 접수 중 | 버튼 `신고 접수 중…` + `disabled`, `이전`·`신고 확정`도 잠금, form `aria-busy="true"`, `⏳ 접수 중 · 신고를 접수하고 있습니다.` | `setSubmitState("loading")` |
| 완료 / 실패 | 성공 → 신고 번호가 적힌 완료 화면. 실패 → `접수 실패 · …` 안내, **입력값 그대로**, 버튼이 `다시 신고하기`로 다시 활성화 | `setSubmitState("error")`, `completeReport()` |
| 브라우저 저장 | 신고 내역을 `localStorage`(`campusLostReports`)에 저장 → 새로고침해도 `내 신고 내역`과 신고 번호가 이어짐. 신고 취소도 저장 | `saveReport()`, `loadReports()`, `storeReports()` |
| 다시 작성 | `다른 물건 신고하기`: `form.reset()` + 조건부 칸 닫기(`disabled`) + 오류·상태 문구·글자 수·상단 안내·버튼 문구/잠금을 모두 처음 상태로 | `handleReportRestart()` |

### 입력 조건

| 항목 | 종류 | 조건 | 오류 문구 (문제 + 고치는 방법) |
| --- | --- | --- | --- |
| 물건 종류 | select | 필수 | `물건 종류를 선택해 주세요. 애매하면 '기타'를 고르세요.` |
| 물건 특징 | text | 필수, 앞뒤 공백 제외 **2자 이상**, 최대 30자 | 빈 값: `물건 특징을 입력해 주세요. 예: 흰색 에어팟 프로` / 짧음: `물건 특징을 2자 이상 입력해 주세요. (지금 1자) …` |
| 이름·표시가 적혀 있음 | checkbox | 선택 | - |
| └ 적혀 있는 이름·표시 | text | **체크했을 때만** 필수, 2자 이상, 최대 20자 | `적혀 있는 이름·표시를 입력해 주세요. 예: 김OO, 2026 스티커` |
| 잃어버린 장소 | select | 필수 | `잃어버린 장소를 선택해 주세요. 모르면 '잘 모르겠음'을 고르세요.` |
| 잃어버린 날짜 | date | 필수, 오늘까지 | `오늘 이후 날짜는 선택할 수 없습니다. 날짜를 다시 골라 주세요.` |
| 연락 받을 방법 | radio | 필수 | `연락 받을 방법을 하나 선택해 주세요.` |
| └ 학교 이메일 | email | **학교 이메일을 골랐을 때만** 필수, `@` 포함, `.ac.kr`로 끝남 | `이메일 형식이 올바르지 않습니다…` / `학교 이메일(.ac.kr로 끝나는 주소)을 입력해 주세요. 개인 메일(gmail 등)은 받을 수 없습니다.` |

- 상태는 색만으로 구분하지 않습니다: 성공은 `✓` + `입력 조건을 충족했습니다.`, 오류는 `!` + 문제와 고치는 방법, 필수 항목은 `필수` 글자, 접수 중·실패는 `⏳ 접수 중 ·`, `접수 실패 ·` 머리말을 붙였습니다.
- 숨겨진 조건부 칸은 `disabled`라서 `FormData`(제출값)와 검사에서 모두 빠집니다. 적어 둔 값은 지우지 않아 다시 체크/선택하면 그대로 보입니다. `aria-controls`·`aria-expanded`로 선택 요소와 추가 영역을 연결했습니다.
- 오류 문구는 입력할 때마다 새로 띄우지 않고, `다음`·Enter·제출 때 표시합니다. 이미 오류가 난 칸만 입력 중에 다시 검사해 고쳐지면 바로 지웁니다.

### 실패 처리 조건

서버 대신 브라우저 저장 공간에 저장하며(`script.js`의 `saveReport()`), 1.2초 동안 접수 중 상태를 보여 준 뒤 다음 경우에 **실패**로 처리합니다.

1. **인터넷 연결이 끊긴 경우** (`navigator.onLine === false`) — 개발자 도구 **Network → Offline**으로 확인할 수 있습니다.
2. **브라우저가 저장을 막은 경우** (`localStorage.setItem`에서 오류: 저장 공간 부족, 사이트 데이터 차단 등)

실패하면 신고 내역에 추가하지 않고, 확인 화면과 입력값을 그대로 둔 채 버튼을 `다시 신고하기`로 다시 활성화합니다.

### 확인 순서 (브라우저에서 직접 조작)

1. `분실물 신고 시작하기` → 아무것도 입력하지 않고 `물건 특징` 칸에서 **Enter** (또는 `잃어버린 장소 입력하기`)
   → 1단계에 머묾, 위쪽에 `수정이 필요한 항목이 2개 있습니다: 물건 종류, 물건 특징.`, 각 칸 아래 오류, `물건 종류`로 초점
2. 물건 종류를 고름 → 그 칸의 오류만 사라짐 / 물건 특징에 `검` 한 글자 → `1 / 30자`, 오류 문구가 `2자 이상 … (지금 1자)`로 바뀜
3. `검정 백팩`으로 고침 → 오류와 상단 안내가 사라지고 초록 테두리 + `✓ 입력 조건을 충족했습니다.`
4. **조건부(체크박스)**: `이름이나 표시가 적혀 있어요` 체크 → 칸이 나타나고 입력 가능 → 비운 채 다음 → 오류 → 체크 해제 → 칸이 사라지고(`disabled`) 오류도 사라짐 → 다시 체크하고 `김OO` 입력 → 다음
5. 2단계에서 그대로 다음 → 장소·날짜·연락 방법 오류 3개 / 날짜 `2099-01-01` → 미래 날짜 오류 → 고치면 해제
6. **조건부(라디오)**: `학교 이메일` 선택 → 이메일 칸 표시 → `me@gmail.com` 입력 후 Enter → `.ac.kr` 오류 → `me@school.ac.kr`로 고치면 `✓ 알림을 받을 수 있는 학교 이메일입니다.` → `직접 문의` 선택 시 칸 숨김·비활성 → 다시 `학교 이메일` 선택 시 값 유지
7. `신고 내용 확인하기` → 확인 화면에 `적힌 이름·표시`까지 표시 (체크 해제 시 빠짐)
8. **실패**: 개발자 도구 Network를 **Offline**으로 → `이 내용으로 신고하기` → `신고 확정`
   → 버튼 `신고 접수 중…`(비활성), `이전`도 비활성 → 1.2초 뒤 `접수 실패 · … 인터넷 연결이 끊겨 있습니다.`, 입력값 유지, 버튼 `다시 신고하기`
9. **정상 제출**: Offline 해제 → `다시 신고하기` → `신고 확정` → 완료 화면 `LF-001`
10. **다시 작성**: `다른 물건 신고하기` → 입력값·체크·라디오, 조건부 칸(숨김·비활성), 오류·상태 문구·글자 수(`0 / 30자`), 상단 안내, 버튼 문구(`이 내용으로 신고하기`)가 모두 처음 상태
11. 새로고침 → `내 신고 내역`에 `LF-001`이 남아 있고, 다음 신고는 `LF-002`

## 중간고사: 7주차에서 새로 추가한 것

7주차에는 신고를 확정하면 완료 화면에서 흐름이 끝나고, 다른 물건을 신고하면 앞의 신고 내용이 사라졌습니다.
중간고사에서는 **완료한 신고를 `내 신고 내역` 목록에 쌓아 다시 열어 보고, 신고 번호·물건 특징·상태로 찾고, 물건을 찾았을 때 사유를 골라 신고를 취소**할 수 있게 했습니다.

### 왜 이 기능인가

분실물 신고를 한 학생이 다음으로 하는 일은 "내가 뭘 신고했더라?"를 다시 확인하는 것, 그리고 물건을 찾으면 신고를 정리하는 것입니다.
신고를 취소하지 않으면 이미 찾은 물건의 습득 알림이 계속 오고, 습득물을 등록한 사람도 헛걸음을 하게 됩니다.
그래서 7주차 흐름의 **끝(완료 화면)** 에 이어지는 행동으로 정했습니다.

### 7주차 흐름과 연결되는 지점

```
시작 → ① 물건 정보 → ② 장소·연락 → ③ 내용 확인 → 완료 ─┬→ [내 신고 내역 보기] → 목록(방금 신고가 펼쳐진 상태)
                                                         │                           ├→ 조건으로 찾기 → 결과 / 결과 없음
                                                         │                           └→ 신고 취소 → 사유 선택 → 취소됨
                                                         └→ [다른 물건 신고하기] → 1단계 (목록에는 계속 남음)
내 신고 내역이 비어 있으면 → [분실물 신고하러 가기] → 7주차 흐름 시작 버튼
```

- 신고를 확정하는 순간(`completeReport`) 입력값을 **복사해서** 목록 맨 앞에 추가합니다. 그래서 `다른 물건 신고하기`로 입력칸을 초기화해도 목록의 내용은 바뀌지 않습니다.
- 메뉴의 `내 신고 내역`, 이용 방법 탭(`물건을 잃어버렸어요`)의 링크로도 이동할 수 있습니다.

### 새 기능의 행동 → 조건 → 반응 → 다음 행동

| # | 사용자 행동 | 확인할 조건 | 성공 반응 | 다른 분기의 반응 | 다음 행동 |
| --- | --- | --- | --- | --- | --- |
| 1 | `내 신고 내역` 영역을 봄 | 접수한 신고가 있는가 | 통계(`전체 N건 · 접수 중 N건 · 취소 N건`)·검색 칸·목록 표시 (최근 신고가 위) | **내역 없음**: 검색 칸을 숨기고 `아직 접수한 신고가 없습니다…` 안내 | `분실물 신고하러 가기` → 분실물 신고 영역의 시작 버튼(이미 시작했다면 지금 단계 제목)으로 이동 |
| 2 | 완료 화면에서 `내 신고 내역 보기` | - | 검색 조건을 풀고 방금 접수한 신고를 **펼친 상태**로 보여 주며 그 위치로 이동 | - | 자세히 보기 / 신고 취소 |
| 3 | 목록에서 `자세히 보기` | - | 연락 방법·접수 시각(취소한 신고는 취소 사유·취소 시각까지) 표시, 버튼이 `접기`로 바뀜 | 다시 누르면 접힘 | 신고 취소 |
| 4 | 검색어 입력 후 `신고 찾기` | 검색어가 `LF`로 시작하면 `LF-001` 형식(LF- + 숫자 3자리)인가 | 신고 번호가 같거나 물건 종류·특징·장소에 검색어가 들어간 신고만 표시, `검색어 '백팩' · 전체 3건 중 1건을 찾았습니다.` | **형식 오류**(`LF1` 등): 입력칸 아래 `신고 번호는 LF-001처럼…` + 빨간 테두리, 이전 결과는 그대로 유지. 글자를 고치면 오류가 바로 사라짐 | 검색어 고치기 |
| 5 | `신고 상태` 선택(전체/접수 중/취소됨) | 선택한 상태와 신고 상태가 같은가 | 바로 해당 상태의 신고만 표시 | - | 검색 / 초기화 |
| 6 | 조건에 맞는 신고가 없음 | 걸러진 결과가 0건인가 | - | **결과 없음**: `검색어 '우산'에 맞는 신고가 없습니다. 검색어를 줄이거나 상태를 '전체'로 바꿔 보세요.` | `조건 초기화하고 전체 보기` → 검색어·상태 초기화, 전체 목록 |
| 7 | `신고 취소` | - | 그 신고 안에 `취소하는 이유` 선택 칸이 열리고 초점 이동 (다른 신고의 취소 칸은 닫힘) | - | 사유 선택 → 확정 / 취소하지 않기 |
| 8 | 사유 없이 `신고 취소 확정` | 사유를 골랐는가 | - | **입력 오류**: `취소하는 이유를 선택해 주세요. 취소하지 않으려면 '취소하지 않기'를 누르세요.` 상태는 그대로 `접수 중` | 사유 선택 (고르면 오류가 바로 사라짐) |
| 9 | `취소하지 않기` | - | - | **취소의 취소**: 취소 칸만 닫히고 `접수 중` 유지, `신고 취소` 버튼으로 초점 복귀 | - |
| 10 | 사유 선택 후 `신고 취소 확정` | 연락 방법이 이메일인가 / 사유가 `물건을 찾았어요`인가 / 지금 `접수 중`만 보고 있는가 | 상태 배지 `취소됨`(회색), 물건 이름에 취소선, `신고 취소` 버튼 사라짐, 통계 숫자 변경, `LF-001 신고를 취소했습니다.` (+ 이메일이면 `이메일 알림도 더 이상 보내지 않습니다`, 찾았으면 `물건을 찾으셨다니 다행입니다!`) | `접수 중`만 보고 있었다면 목록에서 빠진 이유와 `상태를 '전체'로 바꾸면 다시 볼 수 있습니다` 안내 | 자세히 보기로 취소 사유 확인 / 상태 필터 `취소됨` |
| 11 | `조건 초기화` | - | 검색어·상태·오류 초기화, 전체 목록 | - | 다시 검색 |

### 구현 방법

- **HTML**: `#report` 다음에 `#history` 섹션을 추가했습니다. 검색 폼(`#historySearch`, `novalidate`), 안내 문구(`#historyNotice`, `#historyResultText`, `aria-live`), 목록(`#historyList`), 내역 없음·결과 없음 안내(`#historyEmpty`)로 구성했습니다. 완료 화면에 `내 신고 내역 보기` 버튼, 메뉴에 `내 신고 내역` 링크를 추가했습니다.
- **JavaScript** (`script.js` 맨 아래 중간고사 부분)
  - 상태 변수: `reports`(신고 목록), `appliedKeyword`·`appliedStatus`(검사를 통과해 적용된 조건), `openNumber`(펼친 신고), `cancelingNumber`(취소 사유를 고르는 신고)
  - `renderHistory()`: 상태가 바뀔 때마다 목록·통계·결과 문구·내역 없음/결과 없음 안내를 **다시 만듭니다**. 입력값은 `textContent`로만 넣습니다.
  - `getFilteredReports()`: 상태와 검색어 조건으로 `filter()` 합니다.
  - `validateHistoryKeyword()`: `LF`로 시작하는 검색어가 신고 번호 형식인지 검사합니다. 오류는 7주차의 `setFieldError()` / `clearFieldError()`를 그대로 씁니다.
  - 목록 안 버튼은 `data-action`·`data-number`를 붙이고 `#historyList` 하나에 이벤트를 연결해(이벤트 위임) 자세히 보기·신고 취소·취소하지 않기·확정을 나눕니다.
  - 목록을 다시 만든 뒤에도 키보드 위치를 잃지 않도록, 방금 누른 신고의 버튼이나 사유 선택 칸으로 초점을 옮깁니다.
- **CSS**: 검색 폼(넓은 화면 2열 → 768px 이하 1열), 신고 카드(접수 중은 보라 왼쪽 선, 취소됨은 회색·취소선), 상태 배지, 되돌릴 수 없는 행동용 빨간 `danger-button`, 결과 없음 점선 상자, 다크 모드 색을 추가했습니다. 모바일에서는 7주차와 같이 버튼을 꽉 채우고(48px) 다음 행동 버튼을 위에 둡니다.

### 알려 둘 점 (중간고사)

- 신고 내역도 7주차와 같이 화면에만 저장되어 새로고침하면 사라집니다. → **9주차부터 `localStorage`에 저장되어 새로고침해도 유지됩니다.**
- 신고 취소는 되돌릴 수 없습니다. 그래서 바로 취소하지 않고 사유를 고르는 단계와 `취소하지 않기`를 두었고, 취소 버튼을 빨간색으로 구분했습니다.

## 사용자 흐름

```
시작 → ① 물건 정보 → ② 장소·연락 → ③ 내용 확인 (+ 확정 팝업) → 완료
```

| 단계 | 화면 | 사용자가 하는 일 | 필수값 |
| --- | --- | --- | --- |
| 시작 | `분실물 신고` 영역 | `분실물 신고 시작하기` 버튼 클릭 (메뉴의 `분실물 신고`, 이용 방법 탭의 링크로도 이동) | - |
| ① 물건 정보 | 1 / 3 단계 | 물건 종류 선택, 물건 특징 입력 | 종류, 특징 |
| ② 장소·연락 | 2 / 3 단계 | 장소 선택, 날짜 선택, 연락 방법 선택 → `학교 이메일`을 고르면 이메일 칸이 나타남 | 장소, 날짜(오늘까지), 연락 방법, (이메일 선택 시) 학교 이메일 |
| ③ 내용 확인 | 3 / 3 단계 | 입력·선택한 값을 확인하고 `이 내용으로 신고하기` → 팝업에서 `신고 확정` | - |
| 완료 | 신고 완료 | 신고 번호(`LF-001`…)와 연락 방법에 맞는 안내 확인 → `보관 장소 확인하기` 또는 `다른 물건 신고하기` | - |

화면 위쪽 진행 표시(`1. 물건 정보 · 2. 장소·연락 · 3. 내용 확인`)는 현재 단계를 보라색으로, 지난 단계를 `✓`로 표시하고, 완료하면 세 단계가 모두 `✓`가 되며 `신고 완료`라고 표시됩니다.

### 막혔을 때의 경로

| 상황 | 처리 |
| --- | --- |
| 필수값을 비우고 `다음` | 현재 단계에 머무르고, 비어 있는 **모든 칸** 아래에 고치는 방법을 빨간 글씨로 안내 + 빨간 테두리, 첫 번째 오류 칸으로 초점 이동 |
| 오류가 난 칸을 고침 | 그 칸의 오류 문구와 빨간 테두리가 바로 사라짐 |
| 연락 방법을 `보관 장소에 직접 문의`로 바꿈 | 이메일 칸을 숨기고 검사에서도 제외 |
| 확인 화면에서 고칠 내용 발견 | `이전`으로 돌아가면 입력·선택한 값이 그대로 남아 있고, 고친 뒤 다시 `다음`을 누르면 확인 화면이 새 값으로 다시 만들어짐 |
| 확정 팝업에서 `다시 확인하기` (또는 Esc) | 팝업만 닫히고 확인 화면과 입력값은 유지 |
| 완료 후 `다른 물건 신고하기` | 입력·선택·오류·진행 상태를 모두 초기화하고 1단계부터 다시 시작 (신고 번호만 다음 번호로 증가) |

## 구현 방법

- **HTML**: `#report` 섹션 안에 `.report-step` 4개(`data-step="1"~"4"`)를 만들고, 처음에는 `#reportFlow`를 `hidden`으로 숨겼습니다.
  각 입력칸은 `label`과 연결하고, 오류 문구 `p`(`id="…Error"`, `role="alert"`)를 `aria-describedby`로 연결했습니다. 확정 팝업은 `<dialog>`를 사용했습니다.
- **JavaScript** (`script.js` 아래쪽 7주차 부분)
  - `showReportStep(step)`: 해당 단계만 보이고 진행 표시·문구를 바꾸고 제목으로 초점을 옮깁니다.
  - `validateItemStep()` / `validatePlaceStep()`: 비어 있는 칸마다 `setFieldError()`로 안내하고 첫 오류 칸을 돌려줍니다. 학교 이메일 검사는 5주차 알림 신청과 같은 `schoolDomain`(`.ac.kr`) 조건을 씁니다.
  - `renderReportSummary()`: 확인 화면을 **누를 때마다 현재 값으로 다시 만들어서** 수정한 값이 바로 반영됩니다. (`textContent`로 넣어 입력값이 HTML로 해석되지 않게 했습니다.)
  - `handleReportRestart()`: 모든 값·라디오·오류·확인 목록을 지우고 1단계로 돌아갑니다.
  - `handleReportPlace()`: 6주차 탭 함수 `resetTabsAndPanels()` · `activateTab()`을 재사용해 `보관 장소 안내` 탭을 엽니다.
- **CSS**: 진행 표시(현재 `is-current`, 지난 단계 `is-done`), 오류 `has-error`, 완료 화면(초록색), 팝업과 배경을 추가했고 다크 모드 색도 맞췄습니다.
  768px 이하에서는 단계 영역을 꽉 채우고 버튼을 세로로 쌓아 **다음 행동 버튼이 위**에 오도록 했습니다(`column-reverse`, 높이 48px). 확인 목록도 한 열로 바꿨습니다.

기존 기능(테마 전환, 이용 방법 탭, 알림 신청 폼의 글자 수·수신 동의·입력값 검사)은 그대로 유지했습니다.

## 알려 둘 점

- 신고 내용과 신고 번호는 서버로 보내지 않고 현재 열린 화면에만 있습니다. 새로고침하면 신고 번호가 `LF-001`부터 다시 시작합니다. → **9주차부터 브라우저(`localStorage`)에 저장되어 번호가 이어집니다.**
- 연락 방법을 `직접 문의`로 바꿔도 적어 둔 이메일은 지우지 않고 숨기기만 합니다. (9주차부터는 숨길 때 `disabled`도 함께 적용) 다시 `학교 이메일`을 고르면 그대로 보이고, 숨겨진 동안에는 검사와 확인 화면에서 제외됩니다.
